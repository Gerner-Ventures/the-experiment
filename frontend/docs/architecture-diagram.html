The Experiment — Round Data Flow

How WebSocket messages flow through the frontend during a complete game round

BEFORE — Current Round Flow (Broken)

Problem: Meetings, speeches, and social events fire independently with zero coordination. The turn pipeline processes agent_action sequentially, but meeting_start, meeting_speech, and meeting_vote messages arrive during the same phase and update the UI simultaneously. Agents keep animating while the meeting drawer is open. Phase changes arrive mid-turn-queue, causing visual chaos.
  • agent_action → enqueued in turn store (sequential processing)
  • meeting_* → fires directly to socialStore (no queuing, no coordination)
  • agent_speak → fires to socialStore AND marks turn (split ownership)
  • phase_change → updates experimentStore immediately (no turn queue awareness)
  • Turn queue keeps draining during meetings — bubbles overlap with meeting drawer

AFTER — New Implementation (Coordinated)

Solution: All displayable events flow through the turn store as sequenced items. Meetings become a turn phase — the queue pauses regular agent turns while the meeting plays out. Social events (speeches, votes) are batched into the meeting turn. Phase changes wait for the current turn to complete before applying.
  • meeting_start → enqueues a meeting turn that pauses agent turns
  • meeting_speech / meeting_vote → buffered into the active meeting turn
  • meeting_result → completes the meeting turn, resumes agent queue
  • phase_change → enqueues a phase marker in the turn queue (visual only)
  • Agent turns after the meeting resume in order — no overlap
